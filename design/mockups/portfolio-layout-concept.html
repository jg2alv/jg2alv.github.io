Orion Scheduler

A process scheduling simulator designed to make operating-system trade-offs visible, measurable, and easier to explain.

Context
Academic project
Period
2025-01
Discipline
Operating Systems
Role
Core architecture
academicoperating-systemsc

P1P2CPUP3

Scheduling policies are often introduced as formulas and timelines. This project explored how those policies behave as workloads change, and how to compare them without hiding their consequences behind aggregate numbers.

The simulator models processes, arrivals, bursts, priorities, and context-switch costs. A shared event engine keeps every algorithm comparable, while isolated strategy modules implement first-come-first-served, shortest-job-first, round-robin, and priority scheduling. Results are presented as timelines and concise metrics, connecting implementation details to observable behavior.

I designed the event loop, implemented the scheduling interface, documented the main trade-offs, and created repeatable test workloads for validating fairness and waiting-time calculations.

The strongest lesson was that a correct algorithm is only part of the solution. Careful input modeling, deterministic tests, and clear visual explanations were essential for making the comparison trustworthy.
